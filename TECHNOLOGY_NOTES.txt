PROJECT OVERVIEW

Project Name: TOA Personal Copilot
Description: An AI-powered chatbot application with advanced file processing, voice transcription, and vector-based semantic search capabilities.


TECHNOLOGY STACK

Frontend
- Framework: Next.js 16 (React 19)
- Language: TypeScript
- Styling: Tailwind CSS
- State Management: React Context API
- Build Tool: Turbopack

Backend
- Framework: FastAPI (Python 3.12)
- Server: Uvicorn
- ORM: SQLAlchemy
- Database: PostgreSQL (Primary), Chroma Vector Store (Secondary)
- Language: Python

AI/ML Components
- LLM Provider: Ollama (llama3.2:3b)
- Vector Embeddings: mxbai-embed-large
- Vector Database: Chroma DB
- Speech-to-Text: OpenAI Whisper (Base Model)
- Optical Character Recognition: Tesseract OCR

Infrastructure
- API: RESTful API (FastAPI)
- Protocol: HTTP/HTTPS
- Cross-Origin: CORS enabled
- Real-time Communication: WebSocket ready


CORE FEATURES

1. Chat Interface
   - Real-time messaging with AI model
   - Conversation history tracking
   - Multi-conversation support
   - Context-aware responses using last 10 messages

2. File Upload & Processing
   - PDF text extraction (pdfplumber + Tesseract fallback)
   - Image text extraction (Tesseract OCR with multi-config fallback)
   - Automatic text chunking (1000 character chunks with 200 char overlap)
   - Metadata preservation
   - Conversation-scoped document storage

3. Vector Search & Retrieval
   - Semantic similarity search using embeddings
   - Conversation-filtered document retrieval
   - Top-5 relevant chunk retrieval per query
   - Automatic context injection into chat prompts

4. Voice Transcription
   - Audio file upload support
   - WAV format encoding (16kHz sample rate)
   - OpenAI Whisper integration
   - Automatic text insertion into chat input

5. Conversation Management
   - Create multiple conversations
   - View conversation history
   - Switch between conversations
   - Conversation-isolated context (documents don't leak between conversations)
   - Automatic conversation timestamp tracking

6. Settings & Configuration
   - Adjustable LLM temperature (creativity control)
   - Configurable max tokens (response length)
   - User preferences persistence

7. Connection Status
   - Real-time backend connectivity monitoring
   - Visual status indicators


TECHNICAL ARCHITECTURE

Data Flow: Upload to Answer

Upload Phase:
  Image/PDF → Extract Text → Save to Database → Index in Vector Store

Query Phase:
  Question → Search Vector Store → Retrieve Relevant Chunks → Build Prompt → Send to LLM → Generate Answer

Storage Architecture:
  PostgreSQL (Transactional Data)
    ├─ Conversations (metadata, timestamps)
    └─ Messages (role, content, metadata)
  
  Chroma Vector Store (Semantic Search)
    └─ Embedded Document Chunks (with conversation filtering)


DATABASE SCHEMA

Conversations Table:
  - id (UUID, Primary Key)
  - title (String)
  - created_at (DateTime)
  - updated_at (DateTime)

Messages Table:
  - id (Integer, Primary Key, Auto-increment)
  - conversation_id (Foreign Key)
  - role (String: 'user', 'assistant', 'system')
  - content (Text: Full message or file content)
  - message_metadata (JSON: File type, OCR flags, extracted text)
  - created_at (DateTime)

Vector Store Collection:
  - document_id (UUID)
  - page_content (Text chunk)
  - metadata (conversation_id, filename, chunk_index)
  - embedding (Vector: 1024-dimension)

API ENDPOINTS

POST /chat
  Request: { conversation_id, message }
  Response: { response, message_id }
  Purpose: Send message and get AI response

POST /upload
  Request: multipart/form-data { file, file_type, conversation_id }
  Response: { success, conversation_id, filename, preview }
  Purpose: Upload and process files

POST /conversations
  Response: { id, title, created_at }
  Purpose: Create new conversation

GET /conversations
  Response: [{ id, title, created_at, updated_at }]
  Purpose: List all conversations

GET /conversations/{id}
  Response: { id, title, messages }
  Purpose: Get specific conversation with messages

DELETE /conversations/{id}
  Response: { status }
  Purpose: Delete conversation

POST /transcribe
  Request: multipart/form-data { audio_file }
  Response: { text }
  Purpose: Transcribe audio to text

PERFORMANCE CHARACTERISTICS

Latency:
  - Chat response: 2-3 seconds (includes LLM inference)
  - File upload: 500ms-2s (includes OCR/PDF extraction)
  - Vector search: 50ms (embedding + similarity search)

Throughput:
  - Concurrent users: Limited by server resources
  - Messages per conversation: Unlimited (scalable)
  - File size limit: Server configuration dependent

Storage:
  - PostgreSQL: Transactional data
  - Vector DB: Embeddings (persistent, survives restarts)
  - File system: Temporary uploads (deleted after processing)


SECURITY & DATA HANDLING

  - Connection pooling via SQLAlchemy
  - Automatic transaction management

File Processing:

  - Content extracted and stored in database only

API Security:

  - No authentication (can be added)

2. Conversation Isolation: Documents scoped to conversations prevent context mixing
3. Fallback Handling: Always indexes content (OCR success or image metadata)

5. Integrated Voice: Direct audio-to-text conversion with chat integration
6. Real-time Updates: Immediate feedback on uploads and processing


TECHNOLOGY CHOICES RATIONALE

Next.js: Server-side rendering, API routes, TypeScript support, excellent performance
FastAPI: Fast, modern, automatic API documentation, built-in validation
PostgreSQL: Reliable, scalable, supports JSON fields for metadata
Chroma: Lightweight vector store, no separate server needed, SQLite backend
Ollama: Local LLM inference, no API costs, privacy-first approach
Tesseract: Free, open-source OCR, widely supported
LangChain: Standardized LLM interfaces, chainable operations, extensive integrations
